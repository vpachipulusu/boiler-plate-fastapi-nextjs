# Platform models and the Alembic baseline

SQLAlchemy models for the platform database are in `fastapi_backend/app/models/platform/`, one aggregate per file
(`user`, `admin_user`, `organization`, `membership`, `invitation`, `audit_log`, `app_setting`, `feature_flag`,
`email_template`, `seo_meta`, `url_redirect`, `stripe_event`) plus the Freejoy catalogue (`category`, `merchant`,
`offer`, `affiliate_link`, `click_event`, `email_subscriber`), registered in the package `__init__.py`. Alembic revision
`0001` (`alembic_migrations/versions/0001_baseline.py`) creates the platform tables; revision `0002`
(`0002_freejoy_catalogue.py`) adds the six catalogue tables and never edits `0001`.

## Conventions

- Own `MetaData` with a naming convention (`pk_`, `uq_`, `ix_`, `fk_`, `ck_`); composite indexes are named explicitly.
- Typed `Mapped[...]`, snake_case table and column names, plural table names.
- Primary keys are text, generated by `app.core.ids.new_id` (cuid2).
- Timestamps are `timestamptz` with `now()` server defaults; `updated_at` also uses `onupdate=now()`.
- Enums (membership role, invitation status, and the catalogue's offer type, status, freshness, postage kind, user agent
  class, subscriber status and alert frequency) are short text plus a named CHECK, not native Postgres enums, so adding
  a value is a one-line migration.
- Defaults are server-side (`now()`, booleans, strings, integers); the id default and the `updated_at` refresh are
  applied by SQLAlchemy.
- `audit_logs.metadata` is the `metadata` column, exposed as `AuditLog.metadata_` (the name `metadata` is reserved on
  declarative classes). `audit_logs` has no foreign keys, so the trail outlives users and organisations.
- Catalogue enum values are the upper-case names (`FREE_SAMPLE`); the frontend contract in
  `nextjs-frontend/src/lib/catalogue/types.ts` uses lower-case values, so the Phase 2 API schemas convert at the edge.
- Money is an integer in minor units (`offers.postage_amount_minor`) plus a 3-letter currency, never a float.
- Lists the page renders as a whole (offer `description` paragraphs, claim `steps`, a subscriber's `categories`) are
  `jsonb` arrays with a `'[]'` server default; nothing queries inside them.
- Foreign keys state their delete behaviour: an offer's category and merchant are `RESTRICT` (neither can be deleted
  while it has offers), an offer's affiliate links and clicks `CASCADE`, and a click's `affiliate_link_id` is
  `SET NULL` so click counts survive when a link is replaced.
- Strings are `text`; JSON is `jsonb`. A unique constraint already indexes its column, so no second index is added.

## Main tables

| Table | Notes |
| --- | --- |
| `users` | Firebase UID, email, profile, settings, login history and notifications hang off it. No billing columns. |
| `admin_users` | Platform admins with a role and permission list (`app/core/permissions.py`). |
| `organizations` | Unique `slug`; `subscription_tier` (default `free`), `subscription_status`, `stripe_*` and `granted_*` columns used by the billing module. |
| `memberships` | Role `OWNER`, `ADMIN` or `STAFF`; unique `(organization_id, user_id)`; cascades from both parents. |
| `invitations` | Stores a hash of the token, never the token. Status `PENDING`, `ACCEPTED`, `REVOKED`, `EXPIRED`. |
| `audit_logs` | See [backend-audit-logs.md](backend-audit-logs.md). |
| `app_settings`, `feature_flags`, `email_templates`, `seo_meta`, `url_redirects` | Admin settings area. |
| `stripe_events` | Webhook idempotency (billing module). |
| `categories` | Unique `slug`; `short_name`, `intro`, `tint`, `sort_order` (default 0) and `enabled` (default true) carry what the category pages show. |
| `merchants` | Unique `slug`; `website` and `logo_url` are null until a licensed logo exists; `active` (default true). |
| `offers` | Unique `slug`; `offer_type`, `status` (default `DRAFT`), `freshness` (editorial, nullable), `postage_kind`. Carries every field an offer page shows: image tint, label and alt, `steps`, `availability`, `eligibility`, `subscription_terms`, `requires_card`, `last_verified_at`. CHECK: `postage_amount_minor` and `postage_currency` are set exactly when `postage_kind` is `COST`. Indexes `(status, end_at)` and `(category_id, status)`. |
| `affiliate_links` | Per-offer destination and `tracking_id` for a `provider`; `destination_url` is read server-side only. Index `(offer_id, active)`. |
| `click_events` | One row per outbound click. See the privacy rule below. |
| `email_subscribers` | Double opt-in alert subscribers; see the email decision below. |

### Click events are anonymous

`click_events` stores the offer, the link, `occurred_at`, the referrer **host** and a coarse `user_agent_class`
(`DESKTOP`, `MOBILE`, `TABLET`, `BOT`, `OTHER`). It never stores an IP address, a cookie id, a user id, an email, a session
id or the raw user agent, so a click can be counted but never tied to a person. A metadata test fails if a column with
such a name is added; change the rule in this document and the test together or not at all.

### Subscriber email and tokens

`email_subscribers.email` is stored lower-cased. The `citext` extension is not used (it needs `CREATE EXTENSION`, which
managed Postgres does not always allow); instead the service lower-cases before writing and a CHECK
(`ck_email_subscribers_email_lowercase`) makes the database refuse anything else, so the plain unique index is a
case-insensitive uniqueness guarantee. Only a hash of the confirmation token is stored (`confirmation_token_hash`,
unique), never the token. `consent_text`, `consent_at` and `consent_source` record what the person agreed to, when, and
where.

## Subscription plan catalogue

`app/core/plans.py` holds the static plan catalogue (`PLANS`, `get_plan`, `is_within_limit`); it is keyed by the same
values as `organizations.subscription_tier` (`free`, `pro`, `enterprise`). Each plan sets `max_members` (`None` is
unlimited); add further limits as fields ([backend-plan-limits.md](backend-plan-limits.md)). The limit values are
configurable defaults, not product decisions. It has no Stripe calls or tables: billing endpoints and the webhook live
in the Stripe Billing module ([modules.md](modules.md)).

## Migrating

`DATABASE_URL_DIRECT` (an unpooled endpoint) is used by Alembic when set, else `DATABASE_URL`. `sslmode` in the URL is
passed to asyncpg as `ssl`; other query parameters are dropped. Run `alembic upgrade head` only on a database you own.
CI runs `upgrade head`, `alembic check` and `downgrade base` on a Postgres 17 service container.

**Adding a revision.** `uv run alembic revision --autogenerate -m "<what changed>"`, then append the revision id to
`PLATFORM_REVISIONS` in `app/core/platform_schema.py` (`tests/core/test_platform_schema.py` fails until you do), then
run `upgrade head`, `alembic check` and `downgrade base` locally.

**Deploying a migration.** No build or deploy runs migrations (ADR-011). Before or right after the deploy, run
`uv run alembic upgrade head` from `fastapi_backend/` against the production database (`DATABASE_URL_DIRECT`). Until
then every query on the changed tables fails, and `GET /health/ready` (header `X-Internal-Key`) answers 503
`migrations_pending` with `migrations.current` and `migrations.head`.
